# Перенос реальных тендеров из Google-таблицы

Скрипт `sobrat_tendery.py` собирает файл `makety/tendery-dannye.js` из таблицы
«Тендеры» (листы «Тендеры», «Ответы», «статистика»). Все правила переноса,
согласованные с Оксаной 17.09.2026, записаны прямо в скрипте: статусы, дубли,
этапы (ПКО/НДА, основной, переторжка), даты подачи, менеджеры, причины отказа.
Эти же правила — основа загрузки данных в базу будущего сервиса (Next.js + PostgreSQL).

## Как запустить

1. Скачать таблицу «Тендеры» в формате Excel (Файл → Скачать → Microsoft Excel)
   и сохранить как `Импорт/tendery.xlsx`. Ссылку на таблицу в репозиторий не
   записываем — она открывает реальные данные.
2. Собрать данные:
   ```
   python3 Импорт/sobrat_tendery.py Импорт/tendery.xlsx makety/tendery-dannye.js Импорт/otchet.json
   ```
   Нужен пакет `openpyxl` (`pip3 install openpyxl`).
3. Если данные изменились — поднять `TENDER_SEED_VERSION` в скрипте, иначе
   браузер оставит старую копию. При смене версии сервис один раз заменяет
   тендеры в браузере (ручные правки в тендерах пропадут).

## Важно

- Данные тендеров публикуются на сайте с 18.09.2026 (решение Оксаны: не являются
  тайной). Выкладывается только версия «Базовая» (с 01.07.2026); полная база
  с января остаётся локальной. Скачанная таблица (`.xlsx`) и ссылка на неё
  в репозиторий не попадают.
- Номера строк в скрипте (исключения, этапы из «статистики») привязаны к текущей
  таблице: если в ней вставят или удалят строки, их нужно сверить заново.

## Осторожно: ручные привязки по номерам строк (21.09.2026)

В скрипте есть словари, привязанные к **номерам строк** таблицы:
`MANUAL`, `NEW_FROM_ANSWERS`, `SUBMIT_DATE_FROM_STATS`, `RETENDER`,
`MAINSTAGE`, `PROCHEE`, `PKO_REFUSED`, `WIN_DATES`, `PRE_STAGE`,
`FIRST_IS_PKO`, `SUBMITTED_REFUSALS`.

Номера строк в Google-таблице **не постоянные**: новые записи добавляются
не только в конец (на листе «Ответы» — сверху, на листе «Тендеры» между
месяцами есть строки-разделители). После любого пополнения таблицы эти
номера указывают уже на другие тендеры.

Что это значит:

- **нельзя просто перезапустить скрипт на новой выгрузке** — часть подач,
  переторжек и дат побед приклеится к чужим тендерам (проверено 21.09.2026:
  у 8 тендеров сдвинулись даты подачи, у 4 пропал ответственный);
- перед повторным прогоном нужно пересчитать все номера строк на новую
  выгрузку: сопоставить старую и новую таблицы по названию + заказчику +
  дате создания строки;
- либо (лучше) переписать словари на привязку по названию и заказчику,
  а не по номеру строки. Это же правило действует для будущего сервиса:
  строка таблицы — не идентификатор.

Как обновляли данные 21.09.2026 без перезапуска скрипта: статусы и решения
взяты с листа «Тендеры», результаты и новые подачи — с листа «Ответы»,
сопоставление по названию + заказчику, у тендеров-близнецов с одинаковым
названием — по точному совпадению названия и дате создания.
