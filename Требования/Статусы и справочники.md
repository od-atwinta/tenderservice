# Статусы и справочники

Часть общего документа "Карта процесса и требования".

Статус документа: рабочая версия. Дополняется по ходу проектирования.

---

Все справочники ниже редактируются в админ-панели (кто именно может редактировать — указано в комментарии к каждому). Значения перечислены по данным текущей таблицы Тендеры.xlsx и по ответам Оксаны.

| Название справочника | Тип выбора | Значения |
|---|---|---|
| Направления | Множественный выбор — над одним тендером может трудиться несколько отделов сразу | продвижение, техническая поддержка, разработка, аналитика, дизайн, аутстафф |
| Причины отказа | Единственный выбор | нейронка плохо определила, прочее, не наш стек, не наш стек/профиль, не успеваем подготовиться, не проходим по КТ, жесткие условия, малобюджетный, нереальные сроки, отмена заказчиком, закрытая от нас, дубль. Список неполный, будет дополняться. Редактировать может только администратор, остальные пользователи только выбирают из списка |
| Решение об участии | Единственный выбор | участвуем, отказ, на рассмотрении |
| Секция тендера | Единственный выбор для каждой последовательной секции | НДА, ПКО, Основной, Этап 2, Этап 3, Переторжка, RFI |
| Этап процесса | Системное значение, не редактируется в справочнике | Отбор, Изучение, Подготовка, Подача, Итог |
| Статус тендера | Единственный выбор для активной секции | На рассмотрении, Оценка, Формирование заявки, Готово к подаче, Подано, Допущены, Отклонено, Отменено, Без выбора победителя, Завершено без ответа, Не допущены, Выиграли |
| Валюты | Единственный выбор в текущей форме | ₽, USD. По умолчанию — ₽ |
| Типы закупки | Единственный выбор | электронный аукцион, запрос предложений, запрос цен, конкурс, RFI |
| Основания | Единственный обязательный выбор | 223-ФЗ, 44-ФЗ, коммерческие закупки, внутренний конкурс, не указано. По умолчанию — не указано |
| Площадки/источники | Справочник объектов (не простой список значений), редактируют администраторы | Поля каждой записи: название площадки, ссылка на площадку, логин-пароль доступа, пометка "вход по ЭЦП". Согласовано 2026-08-05 |
| Сотрудники/менеджеры | Справочник объектов, редактируют администраторы | ФИО, логин, роль(и), направления, статус (активен/деактивирован). Ведётся на отдельной странице «Пользователи» (пункт сквозного меню, не подраздел Настроек) — `Макеты/пользователи.html`; доступы выдают администраторы; сотрудник сам меняет пароль после первого входа. Согласовано и реализовано 2026-08-05, подробности прав — в `Роли и участники.md` |

Общее правило для всех редактируемых справочников (согласовано 2026-08-05):
значения нельзя удалять, только деактивировать. Деактивированные значения не
показываются обычным пользователям в выпадающих списках, но остаются видны
администраторам в Настройках (и в уже сохранённых тендерах, где значение
использовалось). Переименование уже используемого значения — отдельный
открытый вопрос, см. `Открытые вопросы.md`.

## Настройки → Справочники

Первая рабочая версия подраздела собрана в
`Макеты/настройки-справочники.html`. На странице редактируются направления,
причины отказа, решения об участии, секции тендера, статусы заявки, валюты,
типы закупки и основания. Значения хранятся в общем локальном источнике
`Макеты/справочники.js` (`atvinta_reference_data_v1`) и после сохранения
используются выпадающими списками готовых макетов.

Для справочника статусов используется расширенный редактор с типом статуса и
матрицей разделов.

- **Ключевой** статус относится ровно к одному разделу. Редактор не позволяет
  сохранить такой статус без раздела или с несколькими разделами.
- **Сквозной** статус может быть доступен в нескольких разделах и при выборе
  не перемещает тендер.
- Доступный список статусов и целевой раздел определяются через один общий
  источник `Макеты/справочники.js`
  (`atvinta_status_section_rules_v1`).

Начальная матрица:

| Статус | Тип | Разделы |
|---|---|---|
| На рассмотрении | Ключевой | Ожидают решения |
| Оценка | Сквозной | Новые, Ожидают решения, В работе, Заявки |
| Формирование заявки | Ключевой | В работе |
| Готово к подаче | Ключевой | В работе |
| Подано | Ключевой | Заявки |
| Допущены | Сквозной | Ожидают решения, В работе, Заявки |
| Отклонено | Ключевой | Архив |
| Отменено | Ключевой | Архив |
| Без выбора победителя | Ключевой | Архив |
| Завершено без ответа | Ключевой | Архив |
| Не допущены | Ключевой | Архив |
| Выиграли | Ключевой | Архив |

Статус "Оценка" доступен на любом неитоговом этапе. Он не доступен в
"Архиве", который соответствует итоговому этапу, и не меняет текущий раздел
тендера. Статус "Допущены" также сквозной: он фиксирует положительное решение
по текущей подаче и разрешает создать следующую секцию, но сам по себе не
меняет текущий раздел. "ПКО/НДА", "Переторжка" и "Второй этап" больше не
являются статусами: соответствующие значения перенесены в справочник секций.

Сотрудники/менеджеры получили состав, владельца и первую реализацию
2026-08-05 — не как подраздел `настройки-справочники.html`, а как отдельная
страница «Пользователи» (`Макеты/пользователи.html`), доступная только
Админу и Суперадмину; общий источник данных — `TenderReferences.getUsers()`
в `справочники.js` (`atvinta_users_v1`). Площадки/источники пока остаются
только описанием в таблице справочников выше, без собственной страницы или
подраздела.

В карточке тендера направления показываются отдельной группой пастельных
тегов слева; на той же строке справа, под карточкой срока подачи, находятся
технические теги закупки. Направления редактируются множественным выбором.
Добавление направления сохраняется без дополнительного предупреждения. При
удалении одного или нескольких направлений система до сохранения показывает
подтверждение с названиями направлений и ФИО назначенных участников, которые
будут сняты. Кнопка "Удалить" подтверждает изменение и удаляет этих
участников из карточки; крестик отменяет операцию и закрывает редактор вместе
с окном подтверждения. Изменение направлений и снятие участников записываются
в историю событий тендера.

В сводной таблице (`Макеты/все-тендеры.html`) колонка "Отдел" только для
просмотра — показывает список направлений тендера через запятую. Изменить
направления можно только в карточке тендера, отдельного редактирования в
таблице больше нет. Согласовано 2026-08-05.

## Иерархия многоэтапного тендера

Согласовано 2026-07-30.

Иерархия данных: тендер → последовательные секции → этап процесса → заявки.
По умолчанию у тендера одна секция. Менеджер может включить признак
"Многоэтапный", после чего в карточке становится доступно добавление
следующей секции.

- Секции не выполняются параллельно.
- Новую секцию можно создать только после решения по предыдущей подаче и
  установки статуса "Допущены".
- Отрицательные и итоговые статусы закрывают текущую секцию и не разрешают
  создать следующую.
- Статус "Выиграли" относится только к итоговому результату.
- Завершённая секция сохраняется как неизменяемый снимок. Редактируется
  только текущая активная секция.
- Общий статус тендера и его раздел рассчитываются по активной секции.
- В каждой секции хранится одна или несколько заявок с собственным сроком,
  процентом готовности и ссылками на документы.
- Название секции выбирается в фиксированном процессном порядке: НДА, ПКО,
  Основной, Этап 2, Этап 3, Переторжка, RFI. Это согласованное исключение из
  общего правила алфавитной сортировки выпадающих списков. Значение "Итог"
  в этом выборе не используется.
- У секции есть общий дедлайн с датой и временем подачи. После сохранения
  активной секции он обновляет плашку "Срок подачи" в шапке тендера и общий
  источник данных карточек.
- Документы секции и документы на подачу хранятся в общей библиотеке
  документов. В самой секции сохраняются ссылки на записи библиотеки,
  поэтому один файл можно подключить в нескольких местах без копирования.
- Перед загрузкой система проверяет название файла на точное и частичное
  совпадение. При совпадении открывается предупреждение со списком найденных
  документов. Точное совпадение подключает существующий документ вместо
  создания копии; при частичном совпадении пользователь решает, продолжать
  ли загрузку нового файла.
- Документы на подачу можно добавить с компьютера или выбрать из папок
  подраздела "Документы" Копилки. Их можно скачать по одному или собрать в
  один ZIP-архив.
- На странице тендера название активной секции и название текущего этапа
  выводятся отдельными тегами над карточкой статуса.
- Вкладка "Этапы и заявки" расположена сразу после "Обзора" и показывает
  секции в хронологическом порядке, заявки, сроки, готовность и документы.

Миграция старых значений:

| Старый статус | Секция | Новый статус |
|---|---|---|
| Формируем | Основной | Формирование заявки |
| Подали | Основной | Подано |
| ПКО/НДА | ПКО | На рассмотрении |
| Одобрена | Основной | Допущены |
| Второй этап | Этап 2 | Подано |
| Переторжка | Переторжка | Подано |
| Не успели податься | Основной | Завершено без ответа |
| Контракт заключен | Итог | Выиграли |
| Б/выбора победителя | Итог | Без выбора победителя |
| Отказались сами | Итог | Отклонено |
| Отменено | Итог | Отменено |

## Жизненный цикл тендера (укрупнённые разделы меню)

Направления и статусы выше — детальные поля записи. Поверх них есть более крупная группировка на 5 состояний, по которой строится меню сервиса (раздел "Тендеры" со вкладками, плюс "Заявки"):

| Раздел меню | Что туда попадает |
|---|---|
| Новые | Решение об участии ещё не проставлено либо выбран ключевой статус, закреплённый за разделом "Новые" |
| Ожидают решения | Решение об участии = "на рассмотрении" либо выбран ключевой статус этого раздела |
| В работе | Решение об участии = "участвуем" при отсутствии ключевого статуса другого раздела; рабочие ключевые статусы - "Формирование заявки" и "Готово к подаче" |
| Заявки | Тендер уже подан и находится в работе до получения итога; ключевой статус - "Подано" |
| Архив | Решение об участии = "отказ" или выбран ключевой архивный статус |

Уточнение от Оксаны: отказы и дубли не получают отдельного раздела меню, они сразу уходят в "Архив" вместе с закрытыми сделками.

### Соответствие этапов разделам сервиса

Уточнено 2026-07-30. Этапы жизненного цикла и разделы сервиса соотносятся
напрямую. На странице карточки тендера фактический статус показывается в
самостоятельной карточке внутренней правой колонки основного контента.
Название этапа вынесено в отдельный тег на `12px` выше этой карточки, на
одну горизонталь с фильтрами постоянного списка тендеров. Графический
степпер не используется.

| Этап | Раздел сервиса |
|---|---|
| Отбор | Новые |
| Изучение | Ожидают решения |
| Подготовка | В работе |
| Подача | Заявки |
| Итог | Архив |

Названия в двух столбцах не взаимозаменяемы: слева указан этап,
справа — раздел и отображаемый статус карточки. Поэтому в превью страницы
"Архив" показывается статус "Архив", а "Итог" используется как название
соответствующего этапа жизненного цикла.

### Возврат из Архива

Уточнено 2026-07-27. Админ или суперадмин может вернуть архивный тендер на
один из существующих этапов:

| Выбор в модальном окне | Решение об участии | Статус заявки | Целевой раздел |
|---|---|---|---|
| Новые — отбор | пусто | пусто | Новые |
| Ожидают решения — на рассмотрении | на рассмотрении | На рассмотрении | Ожидают решения |
| В работе — формирование заявки | участвуем | Формирование заявки | В работе |
| В работе — готово к подаче | участвуем | Готово к подаче | В работе |
| Заявки — подано | участвуем | Подано | Заявки |

При возврате прежняя причина отказа очищается. Сам возврат, комментарий,
ответственный и автор изменения сохраняются в истории событий. Назначенному
ответственному отправляется уведомление со ссылкой на карточку в целевом
разделе.

Это первая версия группировки, использована в макетах разделов и в общей
псевдосинхронизации.

### Выбор статуса и подтверждение переноса

- Доступный список формируется по матрице "Статус - раздел".
- Обычный пользователь с правом изменения статуса видит ключевые статусы
  текущего и следующего раздела, а также сквозные статусы, разрешённые для
  текущего раздела.
- Администратор и суперадминистратор видят все статусы.
- Ключевой статус текущего раздела и сквозной статус сохраняются без
  переноса.
- При выборе ключевого статуса другого раздела система показывает окно:
  "Тендер будет перенесен в раздел «Название раздела»" с кнопками "Перенести" и
  "Отмена".
- До нажатия "Перенести" статус, раздел, история и уведомления не меняются.
- "Отмена" закрывает подтверждение и возвращает пользователя к окну смены
  статуса.

## Первое решение (экран "Новые")

Уточнено при проектировании карточного экрана "Новые" (2026-07-17). У тендера в этом разделе только два возможных исхода, а не четыре:

- **Взять в работу** — Решение об участии становится "на рассмотрении", тендер переходит в раздел "Ожидают решения". При этом обязательно выбрать направление (можно несколько) и ответственного.
- **Отказ** — Решение об участии становится "отказ", обязательно выбрать причину из справочника и можно добавить комментарий. Тендер уходит в "Архив".

"Дубль" — больше не отдельное значение Решения об участии, а один из вариантов в справочнике "Причины отказа" (см. таблицу выше). То есть дубль оформляется через кнопку "Отказ" с причиной "дубль", результат тот же: Решение = "отказ", раздел = "Архив".

Значение "участвуем" в справочнике Решения об участии выставляется позже, на втором решении (после детального изучения, см. `Карта процесса.md`, Шаг 4) — не на этом экране.
